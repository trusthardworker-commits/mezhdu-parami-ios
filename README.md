# Между парами — расписание ФИТЭУ для iPhone

Нативный проект SwiftUI + WidgetKit, iOS 17 и новее. Внутри — все **21 группа**, **446 правил занятий** и **53 недели** из двух предоставленных PDF. Интернет, сервер и регистрация в приложении не нужны. Группу можно искать без учёта регистра и пробелов, например `23пижб`.

Это исходный проект. Облачный workflow запускает тесты Swift и собирает неподписанный IPA; установка и проверка настоящего виджета на iPhone выполняются отдельно. Своего Mac и платной Apple Developer для выбранного способа установки не требуется. Пошаговая установка описана в `WINDOWS.md`.

## Если у вас Windows и нет Mac

Свой Mac для сборки не нужен. В проект добавлен `.github/workflows/ios-build.yml`: GitHub Actions запускает тесты Swift и собирает приложение вместе с расширением виджета на облачном macOS runner. Запуск ручной, через **Actions → Build iPhone app → Run workflow**, после загрузки проекта в GitHub-репозиторий. Workflow должен лежать в `.github/workflows` в корне репозитория, а не внутри дополнительной папки из ZIP. В приватном репозитории действуют лимиты и тарифы вашего GitHub Actions; публикация исходников для этого не требуется.

Результат успешного запуска — артефакт `FITeU-unsigned-iPhone` с **неподписанным** `FITeU-unsigned.ipa`. Само наличие workflow не означает, что сборка уже запущена или прошла. Для установки нужна отдельная подпись приложения и расширения. App Groups и другие дополнительные capabilities не используются. Группа каждого виджета хранится в настройке WidgetKit (`AppIntentConfiguration`), а выбор в приложении — локально. Установка и отображение на реальном телефоне требуют проверки после подписи.

Для установки выбран Sideloadly с обычным Apple ID на Windows. Бесплатная персональная подпись требует обновления каждые 7 дней; Sideloadly поддерживает автоматическое обновление при доступном компьютере и устройстве. Сохраняйте расширение `ScheduleWidget.appex` при подписи — его удаление уберёт настоящий виджет. Данные Apple ID вводятся только пользователем в Sideloadly, они не нужны в репозитории или чате. [Официальная страница Sideloadly](https://sideloadly.io/).

Источники: [облачные macOS runner GitHub](https://docs.github.com/en/actions/how-tos/write-workflows/choose-where-workflows-run/choose-the-runner-for-a-job), [AltStore для Windows](https://faq.altstore.io/altstore-classic/how-to-install-altstore-windows), [ограничения Personal Team](https://developer.apple.com/help/account/basics/about-your-developer-account/).

## Открыть на Mac (необязательный локальный вариант)

1. Скопируйте всю папку проекта на Mac и откройте `Schedule.xcodeproj` в Xcode с поддержкой iOS 17+.
2. Выберите схему **ScheduleApp** и симулятор iPhone. Для симулятора можно собирать с `CODE_SIGNING_ALLOWED=NO`.
3. Для установки на настоящий iPhone из Xcode отредактируйте `Configuration/Shared.xcconfig`: задайте уникальный `APP_BUNDLE_IDENTIFIER` и ваш `DEVELOPMENT_TEAM`.
4. В **Signing & Capabilities** обоих targets — `ScheduleApp` и `ScheduleWidget` — выберите одну команду разработчика. App Groups включать не нужно.
5. Соберите приложение и запустите на iPhone. Добавьте «Между парами» через галерею виджетов экрана «Домой», затем удерживайте виджет → «Изменить виджет» → «Группа».

Группа выбирается отдельно в приложении и в каждом виджете. Можно держать на экране несколько виджетов разных групп. Нажатие на виджет передаёт выбранную им группу в приложение через локальную ссылку, без сервера и общего контейнера.

## Что реализовано

- Поиск и выбор любой из 21 группы, сохранение выбора между запусками.
- Расписание по дням, выбор произвольной даты, навигация внутри недели.
- Крупная карточка в приложении показывает превью виджета для выбранной в приложении группы; просмотр другой даты её не переключает. Если виджет настроен на другую группу, его занятия будут отличаться.
- Маленький, средний и большой виджет: до 2, 3 и 6 занятий соответственно, с числом оставшихся занятий. Средний показывает также аудитории, большой — сведения о преподавателе. Полные названия и сведения доступны в приложении.
- Верхняя/нижняя неделя, обе недели, начало/окончание отдельного занятия, исключённые и разовые даты.
- Военное обучение и день курсового проектирования сохранены как события, а не потеряны как пустые ячейки.
- Оригиналы обоих PDF открываются внутри приложения. Расписание открывается сразу на странице выбранной группы.
- Нажатие на виджет возвращает приложение к дню виджета.

## Правило 20:00

Используется календарная дата **в часовом поясе iPhone**:

| Местное время | Дата расписания |
| --- | --- |
| 10 ноября, 19:59 | 10 ноября |
| 10 ноября, 20:00 | 11 ноября |
| 11 ноября, 00:00 | 11 ноября |
| 11 ноября, 19:59 | 11 ноября |
| 11 ноября, 20:00 | 12 ноября |

Верхняя/нижняя неделя вычисляется для **показываемой даты**. В воскресенье 15.11.2026 в 20:00 появляется понедельник 16.11 — уже нижняя неделя.

WidgetKit получает текущую запись и ещё 14 записей на местные 20:00. Прибавляются календарные дни, а не фиксированные 86 400 секунд, поэтому переходы летнего времени учтены. Расписание не требует запуска приложения вечером. iOS контролирует фактический момент перерисовки и получения следующей временной шкалы, поэтому абсолютная гарантия «ровно до секунды» невозможна. После изменения часового пояса откройте приложение для немедленного перепланирования. Документация: https://developer.apple.com/documentation/widgetkit/keeping-a-widget-up-to-date

## Перенос PDF и ограничения источника

Оба PDF являются сканами без текстового слоя. Данные перенесены вручную с визуальной проверкой ячеек; это не универсальный импорт PDF. Повторяемые правила находятся в `tools/build_data.py`; приложение и виджет читают один `schedule.json`.

- Полная ячейка действует обе недели, верхняя половина — в верхнюю, нижняя — в нижнюю.
- Конкретная дата имеет приоритет над положением половины ячейки и обычной парой того же номера. Например, у 25ИТб в верхней половине написано «09.11, 16.11», хотя эти даты относятся к разным неделям. На обе даты используется указанное разовое занятие. Это правило интерпретации PDF явно закреплено в тестах.
- «С даты» и «кроме даты» учитываются дополнительно к недельности. «До 23.11» трактуется как дата строго раньше 23.11 (на пятницы этой группы неоднозначность границы не влияет).
- Сокращения названий сохранены; их расшифровки не придуманы. В отдельных длинных сокращениях возможны ошибки ручного чтения скана — оригинал доступен рядом с расписанием.
- Общего расписания звонков в PDF нет. Поэтому видны **номера пар**, а не вымышленные часы. Особое время физкультуры сохранено в описании там, где оно указано.
- Файл назван «с 09 ноября», но на страницах 1–3 напечатано «с 02.11.2026». Загруженный набор консервативно действует с **09.11.2026**. Более ранние разовые правила сохранены для аудита, но ранние дни не показываются как актуальное расписание.
- Групповые сроки окончания взяты из заголовков: 22, 29 или 30 декабря 2026. На даты после окончания показывается «расписание не загружено», а не «пар нет». Годовой календарь недель не продлевает осеннее расписание на весну.
- У **24ГУб** напечатано окончание **27.12.2025**, у **23Мб — 19.12.2025**, несмотря на заголовок осени 2026. Исправление года не предполагается. Эти группы получают предупреждение, их шаблон доступен в рамках технической границы набора до 29.12.2026. Этот срок **не подтверждён** документом для данных групп.
- Исключения вроде «03.11 дистанционно» оставлены в описании. Изменений, каникул, праздничных отмен или переносов, которых нет в PDF, приложение не предполагает.

## Проверка

На Windows выполнено: `python tools/validate_data.py` — 8 проверок, включая все группы, непрерывность календаря, уникальность правил, отсутствие конфликтующих пар на каждой дате загруженного семестра и контрольные клетки 23ПИжб. Это проверяет данные, а не доказывает компиляцию Swift.

На Mac из корня проекта:

```sh
swift test
xcodebuild -project Schedule.xcodeproj -scheme ScheduleApp -configuration Debug -sdk iphonesimulator -destination 'generic/platform=iOS Simulator' CODE_SIGNING_ALLOWED=NO build
```

`swift test` запускает 10 тестов настоящего Swift-движка: 19:59:59/20:00, полночь, переход недели, Новый год, смену часового пояса и DST, разовые/отложенные занятия, истечение расписания, неизвестную группу, календарь и передачу кириллического названия группы по ссылке виджета.

После успешной сборки проверить в симуляторе и на iPhone:

1. Выбор 23ПИжб через «Изменить виджет» работает во всех трёх размерах; два виджета могут показывать разные группы. Нажатие открывает соответствующую группу в приложении.
2. 11.11.2026 верхняя: ТПР (1), программирование в ССУБД (2). 17.11 нижняя: ТПР (2), АСД (3, 4).
3. 15.11 в 20:00 отображается нижняя неделя 16.11, пары 3 и 4; после полуночи они остаются.
4. Свободный день, истёкшее расписание и неподтверждённый срок отображаются различно.
5. Проверить узкий экран, увеличенный шрифт, длинные названия, 6 пар у 24ПИжб и открытие PDF. В виджете длинные названия сокращаются; полная версия доступна по нажатию.
6. Перезапуск устройства, закрытое приложение и смена часового пояса не теряют выбранную группу; после смены зоны открыть приложение.

## Файлы проекта

| Путь | Назначение |
| --- | --- |
| `Schedule.xcodeproj` | Готовая структура двух targets и схема запуска |
| `ScheduleApp/ScheduleApp.swift` | Интерфейс, поиск группы, выбор даты, просмотр PDF |
| `ScheduleWidget/ScheduleWidget.swift` | Виджет и заранее рассчитанная временная шкала |
| `Shared/ScheduleCore.swift` | Общая модель, календарь и фильтрация занятий |
| `ScheduleApp/Resources` | Структурированные данные и оригинальные PDF |
| `Configuration/Shared.xcconfig` | Подпись и идентификатор приложения для необязательной локальной сборки |
| `Tests/ScheduleCoreTests.swift` | Исполняемые на Mac тесты Swift-движка |
| `tools/build_data.py` | Проверяемая ручная транскрипция всех групп |
| `tools/validate_data.py` | Проверка структуры и контрольных данных |
| `tools/generate_project.py` | Воспроизводимая генерация Xcode-проекта без XcodeGen |

Для изменения расписания отредактировать транскрипцию, выполнить `python3 tools/build_data.py` и `python3 tools/validate_data.py`, затем пересобрать приложение. Автоматическое получение новых расписаний и импорт произвольных PDF в этой версии не реализованы по исходной договорённости.
